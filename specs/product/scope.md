# Scope

## Current Phase

Pekopeko is currently in the FOUNDATION / DISCOVERY phase, transitioning into the PRODUCT DEFINITION phase. This means:

- No production feature is considered implemented
- No final database technology has been selected
- No final vector database has been selected
- No graph database has been selected
- No final frontend framework decision should be assumed unless already present in the repository
- No final LLM provider architecture should be assumed
- No final agent architecture should be assumed

## Product Definition Phase

The project is now entering the Product Definition phase, where we will rigorously define:
- Core product model and user needs
- Specific capabilities and their value propositions
- Clear boundaries and non-goals
- Detailed scope for future implementation

## Confirmed Goals

At this foundational stage, the goals are:

1. Establish a modular architectural foundation
2. Define core principles and patterns for system development
3. Create a shared understanding of the system's purpose and direction
4. Set up documentation practices and standards
5. Begin defining module interfaces and boundaries
6. Establish testing and development practices

## Candidate Capabilities

The following capabilities are being considered for inclusion in the system, though specific implementations are not yet defined:

- Personal knowledge management
- Multi-modal learning (text, voice)
- AI agent orchestration
- Data ingestion pipelines
- Retrieval and reasoning systems
- Persistent memory systems
- Language learning modules

## Explicitly Out of Scope for the Foundation Phase

The following items are explicitly out of scope for the current foundation phase:

- Full implementation of any specific learning modules
- Final database schema design
- Specific LLM provider selection and integration
- Complete UI/UX design
- Authentication and authorization systems
- Deployment and CI/CD pipelines
- Production-grade performance optimization
- Specific agent architectures
- Integration with external services

## Open Product Questions

1. What specific user needs will drive the prioritization of future features?
2. How should personal knowledge be structured to support both recall and reasoning?
3. What level of persistence and continuity is required for user experience?
4. How should different learning modalities be integrated?
5. What are the privacy and data ownership implications of various approaches?

## Open Architectural Questions

1. What is the optimal balance between modularity and shared infrastructure?
2. How should modules communicate with each other while maintaining loose coupling?
3. What patterns should be used for persistent data management across modules?
4. How can we ensure consistent observability across all system components?
5. What testing strategies are appropriate for AI-integrated systems?
6. How should we handle the evolution of interfaces as modules develop?
7. What are the best practices for managing dependencies between modules?
